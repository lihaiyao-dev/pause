**本轮重新完成 10,000,000 个 ASan 模型事件，退出码 0，耗时 967.86 秒，无超时或 ASan 报告。** 另完成最新测试源码的定向回归、64 层完整模型场景、真实并发和生命周期实验。未确认文档使用契约内的新设计缺陷，但第 9.3 节已有的外部 stopped 转 value 后保留 frame 的循环等待风险仍成立。

## 审查结论

在文档规定的串行 branch 使用、结构化所有权及宿主保活前提下，未确认新的责任计数、完成权竞争或父子退役错误。主要依据如下。

| 设计路径 | 审查结果及证据 |
| --- | --- |
| fork 与暂停并发 | 第 8.1 节在同一锁内撤销 parent、登记全部 children，最后才检查收敛，不存在中途把屏障判为 Paused 的窗口；嵌套模型逐事件重建 live/pending/直接 child 关系 |
| SingleStep | 第 5.3 节先建立下一轮未到达责任，再交付旧批次；恢复调度 stopped 由第 6.3 节撤销下一轮 pending；模型覆盖旧批次未交完时重入和再次 fork |
| Resume 与 callback | 第 7 节通过同一锁下的 phase 唯一裁决；显式 callback reset 在锁外且只有一个清理方，避免双完成、双 reset 和持锁注销死锁 |
| 构造期取消 | callback 尚未构造返回时只记录 CancelRequested；新增深层 parent 预取消场景确认不错误地重新登记责任或提前减少祖先 child 数 |
| parent 重入与 epoch | 最后 child record 退役只减少直接 child 数；parent 下一暂停点原子重新参与并检查门。同轮 Paused 重入保留 epoch；模型覆盖与两个控制方的全部顺序 |
| stopped 与 frame 退役 | 取消撤责和 record 退役分开；新增真实 task 中间态断言在逐层 join 尚未完成时验证 stopped frame 保留，error 则先释放已完成子树 |
| completion 内销毁 | terminal CPO 后不再读取 operation。新增真实 callback/let_stopped/run_loop 实验让外层 operation 在原 terminal 调用尚未返回时销毁，两种销毁方式均通过 |
| Source 与 stop source 释放 | 第 12 节明确要求覆盖 start、通知、callback、request_stop 的实际调用期；计数归零、waiter 为空和根 completion 均不单独构成析构许可 |

这不是对所有调度或 C++ 内存交错的证明。尤其模型要求旧 operation 已 Reap 才复用 branch，比文档允许公开 completion 后立即复用更保守；真实 Pause 的这一边界仍需实现后验收。

## 必须保留的组合风险

第 9.3 节已经记录的循环等待仍然成立：A 持有 branch，在普通外部 sender 上 stopped；外层 `stopped_as_optional` 把它转换成 value，但 A frame 留到整个 join 才释放。B 在暂停点等待时，A 的责任仍有效，屏障可能一直 Collecting：A 退役等 join，join 等 B，B 等屏障收敛后 Resume。

这不是新增的锁内算法缺陷，也不能用额外 Resume 修复。推荐顺序沿用现有设计：

1. 能修改 A 时，在 A 内处理预期的局部停止并正常返回业务结果。
2. 要保持 A 接口时，用第 9.3.1 节的 task 包装，在向 join 交付 value 前释放 A 的内部等待 operation/frame。
3. 业务允许整组停止时，保留 when_all 的取消传播。

本轮重新运行保留 frame 的反例和包装后的释放实验；未改公共 API 或引入新清理机制。

无栈协程表示挂起状态不依赖独立调用栈，不表示同步 completion、取消回调和析构完全不使用普通 C++ 栈。本轮没有重新扫描栈极限，也没有将此前的深层栈耗尽列作本轮设计缺陷。
